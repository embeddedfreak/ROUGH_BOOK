1. First understand: What is a string in C?
The most important interview statement is:

C does not have a built-in string data type. A C string is a sequence of characters terminated by '\0'.

For example:

char str[] = "Hello";

Memory:

Index:   0    1    2    3    4     5
       +----+----+----+----+-----+-----+
Value: | H  | e  | l  | l  | o   | \0  |
       +----+----+----+----+-----+-----+

So:

"Hello"

contains 6 characters in memory, not 5.

The fifth character is:

'o'

and the sixth is:

'\0'

The '\0' is what tells string functions where the string ends.

2. Declaration vs initialization
This distinction is extremely important for interviews.

Declaration
char str[10];

Means:

Create an array capable of storing 10 characters.

At this point, you have allocated storage.

But you haven't intentionally given it a string value.

Conceptually:

str
 ↓
+----+----+----+----+----+----+----+----+----+----+
| ?? | ?? | ?? | ?? | ?? | ?? | ?? | ?? | ?? | ?? |
+----+----+----+----+----+----+----+----+----+----+

For an automatic local variable, the elements have indeterminate values until you initialize them.

3. Initialization
Case 1
char str[] = "Hello";

This is valid.

The compiler determines the size from the initializer:

'H' 'e' 'l' 'l' 'o' '\0'

Therefore:

sizeof(str) == 6

This is one of the most useful things to remember.

The compiler effectively creates:

char str[6] = {'H', 'e', 'l', 'l', 'o', '\0'};

4. Why is char str[]; not allowed?
This is your main question.

char str[];

is not a complete declaration of an ordinary array object because the compiler doesn't know how much storage to allocate.

Think:

char str[?];

What should ? be?

char = 1 byte

char str[10];  → 10 bytes
char str[20];  → 20 bytes
char str[100]; → 100 bytes

But:

char str[];

gives the compiler no size and no initializer from which the size can be determined.

Therefore it doesn't know the size of the object.

But this works:
char str[] = "Hello";

Because the compiler can calculate:

H e l l o \0
      ↓
    6 chars

So:

char str[6];

is inferred automatically.

The C language allows an array of unknown size to have its size determined by an initializer; a string literal is one such initializer for a character array.

If interviewer asks:

Why is char str[]; invalid?

Say:

"str is an array whose size has not been specified. Without an initializer, the compiler has no information from which to determine the array size, so it cannot allocate storage for the object."

That's the clean answer.

7. char *str = "hello" — VERY IMPORTANT
You wrote:

char* str = "hello";

This needs special attention.

A string literal such as:

"hello"

is a string literal stored somewhere in the program's memory.

A pointer can point to it:

const char *str = "hello";

For modern C programming, prefer const char * when you don't intend to modify the literal.

12. Array and pointer are NOT the same
Another major interview topic:

char str[] = "Hello";

str is an array.

Whereas:

char *str = "Hello";

str is a pointer.

They may behave similarly in some expressions, but their types and storage are different.

For example:

sizeof(str)

with:

char str[] = "Hello";

gives:

6

But with:

const char *str = "Hello";

it gives the size of the pointer, typically:

4 bytes

on a 32-bit system or:

8 bytes

on a 64-bit system.

31. Buffer size and overflow
This is particularly important for embedded interviews.

Suppose:

char str[5] = "Hello";

There is a problem if you intend to use it as a normal null-terminated string.

You need:

H e l l o \0

which requires:

6 bytes

The C standard permits an explicitly sized character array initialized from a string literal to omit the null character if there isn't room, but then it isn't a null-terminated string.

So understand:

char str[6] = "Hello";  // room for '\0'

versus:

char str[5] = "Hello";  // no room for '\0'
